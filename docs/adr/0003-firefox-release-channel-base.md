# Kyber Fox builds on the Firefox release channel, reassembled from the tarball each time

Kyber Fox follows Firefox's release channel, not ESR, and keeps no long-lived fork branch: every build starts from the pinned official release tarball and reapplies LibreWolf's kept patches, Kyber Fox's patch series, the overlay and the settings, in that order. ESR was considered and rejected because LibreWolf, whose patches Kyber Fox builds on, tracks release; because ESR ships only the security fixes Mozilla chooses to backport; and because its features lag by up to a year, then arrive in one large yearly rebase. The cost is a new base every two weeks (Firefox's cadence since version 155), which the upstream watch and a small, single-purpose patch queue are there to absorb. If Kyber Fox repeatedly misses its 72-hour security target because of rebase work, moving to ESR is the fallback, with this ADR superseded. The comparison is in [architecture.md](../architecture.md#release-or-esr).
